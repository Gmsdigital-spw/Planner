# Trading Floor V6 spec — Alpaca day trading, paper first

_Standing instructions written with Grayson on Oct 20, 2026; updated Oct 23, 2026 (pre-trade risk check, nightly journal review, daily plan checklist, data-only rules, go-live checklist; see "Rules added Oct 23, 2026" below). Not financial advice: even with every rule here the account can lose the $25. The floor is built and gated; nothing trades until the key tap and a separate "paper go", and nothing trades real money until a separate "live go" with its own key._

## The money rules (enforced twice: in the gateway code `gw/run.py` op `alpaca`, and in the run prompt)
| Rule | Value |
|---|---|
| Deposit | $25 (paper money for the first 2 trading days) |
| Hard floor | $20: equity at or below the floor = every new buy is refused by the gateway, open positions are closed, the floor stays locked until Grayson resets it |
| Max total loss | $5, by construction (deposit − floor) |
| Risk per trade | 2% of equity ($0.50 on $25) |
| Stop-loss | on every buy, placed with the entry as a bracket order; a buy without one is refused |
| Take-profit | at least 2:1 reward-to-risk or the trade is skipped |
| Position size | risk ÷ (entry − stop) in notional dollars (fractional shares); max 40% of cash in one name; max 2 open positions |
| Hours | buys 8:35 AM to 2:45 PM Central only (market opens 8:30 CT); everything flat by 2:45 PM; no overnight holds; day orders only |
| Daily loss limit | $1.50 (6% of $25): hit it and Bear closes the day |
| No margin | cash only; buying power = cash; never short, never options, never crypto |
| Paper → live | 2 paper trading days (Grayson shortened it from 14 on Oct 20, 2026) with the report below, then Grayson's separate "live go"; live uses a different key and the ALPACA_LIVE variable set to 1 by Grayson himself |

## The crew
- **Bull** — finds long setups in liquid large-cap names and ETFs only (price above $5, average volume high, tight spread): trend on the 5-minute chart + a pullback to a level, entry on the first green bar, stop under the pullback low, target at 2R; every level from 5-minute bars fetched in the same run ("Chart analysis" below). Writes each idea as a TradePlan: symbol, entry, stop, target, R:R, size, one-sentence reason, confidence (decision → number → next action).
- **Bear** — the risk officer. Checks every plan against the rules table and the pre-trade risk check (below) before any order; owns the floor, the daily loss limit, the 2:45 PM flatten; the only one allowed to lock or (never without Grayson) unlock the floor. Bear's "no" ends the discussion.
- **Vault** — the ledger: every order, fill, fee, slippage, equity curve, drawdown; writes modules/trading/ledger/<day> and the running 2-day paper report (win rate, average R, max drawdown, biggest loss, rule breaches = must be 0); runs the nightly trade-journal review (below) in the close run.
- **Tape** — the morning read in plain English: what the market did yesterday, what is on the calendar today (earnings, Fed, CPI), what the crew will and will not touch. Uses the glossary words and explains each one the first time it appears in a day. Owns the daily plan checklist (below); the read sets only the bias and the avoid list, never a price target.

## The paper report (2 trading days) (Vault, in the app under the Trading Floor)
Per day: trades, wins, losses, net P/L, max drawdown, rule breaches. Totals: win rate, average R, expectancy, worst day, best day, breaches (must be 0 to be allowed to ask for live). The report never predicts; it describes.

## The Trading lab (nightly backtests on days the bot has never seen) — added with Grayson Oct 20, 2026
- **What:** `factory/trading/backtest.py` replays the exact strategy on real past 5-minute bars (free Alpaca IEX feed) as a $25 account with every rule and a realistic cost per trade (spread + slippage). It runs in the free GitHub Action "Trading lab" when a job is pushed to `factory/trading/lab/jobs/`. Each result reports trades, win rate, average R, profit factor (gross profit ÷ gross loss from the replayed trades, after costs; added Oct 23, 2026; `null` when no trade lost, never a made-up value), net P/L, max drawdown and breaches.
- **Honest test (walk-forward):** each job has TUNE days (where candidate settings are compared) and HOLDOUT days (never used for tuning). A change is only "adoptable" if, on the HOLDOUT days, it beats the current settings on net P/L and average R, with 20+ trades, no worse drawdown and 0 breaches.
- **Adoption:** only the Trading lab run writes `factory/trading/params.json`, and only after a change has been adoptable on TWO different holdout sets in a row. Bull uses params.json values where set (and its `setupNote` when a new setup type was adopted). The lab can never change the money rules (bankroll, floor, 2% risk, 40% cap, 2 positions, $1.50 daily loss, 2:1 minimum, flat by 2:45).
- **Live gate:** the crew does not recommend "live go" until the latest lab result for the CURRENT params shows positive net P/L on its holdout days with 20+ trades. First result (Oct 20, 2026, baseline): tune 22 trades / 31.8% wins / −$0.36; holdout 30 trades / 20% wins / −$1.06. Not ready. Latest (lab-2026-10-22, current params): holdout 28 trades / 14.3% wins / avg R −0.29 / −$0.54 / drawdown $0.54 / 0 breaches. Not ready. The full gate is the go-live readiness checklist below.

## Rules added Oct 23, 2026 (from Grayson's review of 7 outside "stock trading automation" prompts; only the parts that run on real Alpaca data were kept, rewritten as agent rules)

### No number without data (all four agents, every run)
- Every number in a plan, verdict, ledger line, report, journal, skill line or message names the source read in the SAME run: a gateway result (`/bankroll`, `/positions`, `/orders`, `/clock`, bars, snapshots), the autopilot's day file or heartbeat, a lab result file, or the database record it was written to earlier.
- Source missing or failed = write `unknown (source: <where it will come from>)`. Never an estimate, a rounded guess, a remembered price, a level from the news, or a number copied from an older day.
- A number with no source goes in the ledger's `reportSlips` list with who wrote it; `breaches` stays for money-rule breaches only, so the paper report's "mechanics OK" verdict keeps its meaning.

### Bear: pre-trade risk check (before any order the crew sends; and on every autopilot entry at the next scan)
Read `/bankroll`, `/positions`, `/orders?status=open` and, for today's realized loss, the day file's `trades[]` (or `/orders?status=closed&after=<today 8:30 CT>`) first; the check uses only those numbers. Any line fails = "NO + the line", no order. On the next scan Bear re-checks each autopilot buy from what the day file recorded (positions open at that minute, their stops, the notional): a buy that broke a money rule is a breach; one that fails only Bear's arithmetic (lines 1 to 4) goes in the ledger's `bearFlags` list, not `breaches`. Floor room is checked live only.
1. **Floor room** = equity − $20 floor − open risk, where open risk = Σ (entry − current stop) × qty over open positions. Floor room must exceed this plan's risk dollars (2% of equity), so the account stays above the floor even if every stop fills. Floor room under $1.00 is a warning Bear sends Grayson once that day (one line), not an entry rule: the coded floor is $20 and only Grayson changes money rules.
2. **Day room** = $1.50 daily loss limit − today's realized loss (closed trades) − open risk. Day room must exceed this plan's risk dollars.
3. **Open exposure**: open positions + this one ≤ 2. SPY, QQQ, DIA and IWM count as ONE bet (the one-bet rule, same words everywhere): the combined open risk across them stays within one trade's 2% of equity, and a second index ETF while another is open is at most half size; Bull sizes it so, Bear checks it, Vault's journal flags "combined index risk over 2%".
4. **Max loss vs floor**: equity − open risk − this plan's risk must stay above $20; otherwise NO, whatever the setup looks like.
5. **The rules table** as before: a stop at least 0.3% under entry, target ≥ 2:1, notional ≤ 40% of cash and ≤ cash, 8:35 AM–2:45 PM CT, day order, not on today's avoid list.
Bear writes one line per plan: `GO|NO <SYM>: floor room $x.xx, day room $x.xx, exposure n/2 (index bet $x.xx of $x.xx), max loss to floor $x.xx` (numbers from this run's gateway reads). In code today the autopilot and gateway enforce: the floor (equity at or below $20 = no buys, flatten and lock), the $1.50 daily loss limit on day P/L marked to market (realized + open, equity minus equityOpen), a stop on every buy, the 40% cap, the hours, 2 positions and 4 entries. The open-risk arithmetic of lines 1, 2 and 4 and the one-bet rule of line 3 are Bear's checks, not yet code.

### Bull: chart analysis only from bars fetched this run
- Every level (VWAP, 20-bar average, pullback low, opening-range high and low, entry, stop, target) is computed from 5-minute bars fetched through the gateway in this run (`/stocks/bars?symbols=...&timeframe=5Min&feed=iex`, start = today's 8:30 CT open) plus the latest trade (`/stocks/<SYM>/trades/latest?feed=iex`). Bull names the bar time each level came from.
- Fewer than 4 completed bars since the open, or a failed bars job = `no data: <reason>`, no plan. A 20-bar average exists only once 20 completed bars exist today (10:10 CT); before that it is `unknown (source: bars)` and no pullback plan is possible (the autopilot's own setup fires from the 22nd bar, about 10:20). Never yesterday's bars, a remembered level, a round number, or a level from the news or the read (this supersedes the Oct 21 note about fetching with start = prior day).
- A TradePlan lists: symbol, bars used (count, first and last bar time), entry, stop (which bar's low it sits under), target, R:R, size, one-sentence reason, confidence. Decision → number → next action.

### Vault: nightly trade-journal review (part of the close run, after the flatten and the ledger)
1. Read `factory/trading/auto/<day>.json`: `trades[]` (entry, exit, r, why), `actions[]` (times, status codes, qty, stop), `equityOpen` → `equity`, `entries`, `watch`, `avoid`, `lastNote`; exit times from `/orders?status=closed` when the day file has none.
2. Find recurring errors: anything that happened twice today or on 2 of the last 3 journals (read both journal locations). Look for: refused orders (any action with status ≥ 300); exits with why `no stop` or `trail refused`; combined index risk over 2% (the one-bet rule); a −1R stop within 15 minutes of entry; an entry in the last 30 minutes of the window (13:30 to 14:00); a winner sold under 2R without a trailed stop; a name traded while on the avoid list (the 15-minute and 30-minute thresholds were set by Grayson's Oct 23, 2026 review and move only on journal evidence). Quote the times, symbols and numbers from the day file.
3. Write `factory/trading/journal/<day>.md`: the day's numbers (trades, wins/losses, net $, equity open → close, breaches), a trade table (symbol, in, out, R, why, entry time), "Recurring errors" with the evidence, and exactly 3 rules for tomorrow. Each rule names the number it rests on and the check that proves it tomorrow (for example "0 actions with status ≥ 300 in tomorrow's day file"). A rule may tighten, never loosen, a money rule or a LOCKED knob, and never tells the autopilot a price.
4. No-trade day: say so, with the reason from `lastNote`; carry yesterday's 3 rules forward and mark each held / not held. Invent nothing.
5. One dated line in Vault's "What I've learned": the journal file and the single most important rule.
(Until Grayson adds `factory/trading/journal/` to the close task's write list, Vault writes the journal under the skills folder it may already write, `factory/skills/vault/journal-<day>.md`, and says so in the ledger.)

### Autopilot trail-stop fix (Oct 23, 2026)
- **What happened (Oct 22):** both winners (XLF 11:29, WMT 14:35) exited via `trail refused (422) → no stop found → market sell`. The day file shows the refused orders were sent with `qty "0"`: the autopilot took Alpaca's `qty_available`, which is 0 while the protective stop order holds the shares (and the string "0" is truthy, so the fallback to `qty` never ran). The fail-safe market sell went out with `qty "0"` too and was refused, so each name sat without a stop for about one minute until the next cycle sold it.
- **Fix (factory/trading/autopilot.py):** stop re-places and sells use the whole position `qty`; the old stop's cancel is confirmed by reading the order back before the new stop is placed (then the live position qty is re-read); one retry 2 s later; if Alpaca still refuses, the existing fail-safe sells at market with the right qty and the trade is recorded honestly as `trail refused` with its real R; if the old stop filled during the cancel, nothing more is sent. No money rule, LOCKED knob or exit level changed.
- **Verified when:** a paper day's file shows at least one `raise stop` action with a `qty`, no action with status ≥ 300 and no buy with status 207. Until then the fix is "in code, not yet seen live".
